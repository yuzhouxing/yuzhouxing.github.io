插件流程进阶教程
代码块中每条命令单独一行，条件下面的命令统一缩进四个空格。

一、先弄懂三件事

工作流程：具体做什么，例如走路、等对白、进入墓园。
触发器：什么时候开始做，例如时间到了20:00:00，或者收到指定提示。
条件判断：现在能不能做，例如人在不在正确房间、是否空闲。

正确结构：
触发事件发生 → 检查条件 → 执行已测试过的流程 → 停止或关闭触发。

时间到了，不代表角色自动具备任务资格。
进入药王谷，也不等于完成药王谷，更不等于已经抢到谷主。

二、先做一个不会花钱、不会战斗的定时测试

第1步：创建普通工作流程。
名称：药王谷执行
内容：

```flow
@print 药王谷定时执行测试开始
look
@print 测试结束，本段没有执行战斗或提交剧情
```

先保存，手动点一次运行，确认能看到两条测试信息。
这是演练内容，不是完整药王谷通关路线。

第2步：创建触发器。
进入“触发器” → 新建 → 选择“时辰已到”。
名称填写：药王谷20点启动
条件填写：
时：20
分：0
秒：0

动作源码填写：

```flow
@off 药王谷20点启动
[if] (:combating) == true
    @print 当前正在战斗，本次未启动
    [exit]
[if] (:free) == false
    @print 角色当前不空闲，本次未启动，请手动检查
    [exit]
@call 药王谷执行
```

保存后，还要把触发器切换成“已开启”。只保存不一定代表已开启。

解释：
@off 药王谷20点启动：先关闭这个定时触发，防止后续重复触发；不会中断这次已经启动的动作。
(:combating)：是否正在战斗。
(:free)：检查插件识别的忙乱、昏迷等动作限制，不等于已脱战，也不能代替提前停止打坐。
[if] 条件：条件成立才执行下面缩进的内容。
[exit]：结束当前流程，不是退出游戏。
@call 药王谷执行：调用前面保存的普通流程，名字要完全一致。

第一次测试不要真的等到晚上：
把时、分、秒改成设备当前时间之后一两分钟，保持游戏前台在线，观察能否触发。
测试成功后改回目标时间，并重新开启。
由于示例触发后会自我关闭，第二天想再用，需要手动重新开启。

三、20点用的是哪个时间？这点一定要看

“时辰已到”读取玩家手机／电脑浏览器的本地时间。
药王谷谷主轮次按服务器时间的每天20点划分。
两者不是同一个时钟来源。

例如：如果服务器按北京时间，服务器20点对应泰国时间19点；
人在泰国、设备也设置为泰国时区，就应根据这一对应关系设置触发器。
这只是时区换算示例，不是在断言所有服务器都采用北京时间。

另外：
· 页面关闭、掉线、设备休眠，都无法保证触发执行。
· 手机锁屏或切后台，浏览器可能暂停／延迟计时。
· 精确到“秒”的条件，错过该秒通常不会自动补跑。
· 网络延迟仍会影响命令到达服务器的时间，插件无法保证第一名。
· 不要同时在多个页面、两个设备上给同一角色开启同一个抢跑流程。
· 先同步设备时间，并向管理员确认活动使用的服务器时间。

四、药王谷20点：有两种用法，不要混在一起

用法A：20点开始跑整条剧情。

把“药王谷执行”里的测试内容，换成你已经手动跑通的实际剧情流程。
触发器仍然使用第二节的写法。
到点只是从头开始执行，最后完成得比别人慢，当然不一定拿到本轮谷主。

准备路线时：
1. 提前手动完成一遍，打开“代码：开”，记录实际操作命令。
2. 去掉日志前的时间，只保留命令。
3. 对白要等提示，战斗要等结束，不能只靠一串固定延时硬冲。
4. 活人物ID可能每次不同，优先使用插件支持的按名称查找写法。
5. 路线必须明确从哪里开始，不能角色站在哪里都执行同一串方向。
6. 新玩家剧情、重走旧事、救人线、杀局线，不能混用同一份路线。

不要把“jh ar 6 start”当成提交谷主的命令。
它只是进入公共药王谷入口；在已经推进剧情的情况下返回公共入口，还可能清掉本轮剧情阶段。
当前内置一键副本列表也不能据此假定存在“@fb 药王谷”完整通关流程。

用法B：前置已做完，只在20点走最后的墓园结算。

当前源码里，杀局线完成地火窟残魂环节后，首次进入墓园会触发后续剧情，并尝试结算本轮谷主。
不是点一下按钮就跳过整个药王谷。

下面这个“最后一步”流程，仅适合满足全部条件的玩家：
· 已经完成当前这一轮的地火窟残魂环节。
· 当前这一轮还没有进墓园完成结算。
· 站在这一轮正确剧情进度对应的“药王谷-山谷尽头”。
· 已脱离战斗、没有忙乱或打坐等阻碍移动的状态。
· 自己确认准备的是杀局线谷主结算，不是救人线，也不是百草渊。

把普通流程“药王谷执行”改为下面内容：

```flow
[if] (:combating) == true
    @print 当前正在战斗，停止执行
    [exit]
[if] (:free) == false
    @print 当前不空闲，停止执行
    [exit]
[if] (:room 药王谷) == false
    @print 当前不在药王谷，停止执行
    [exit]
[if] (:room 山谷尽头) == false
    @print 请先站到正确剧情进度下的山谷尽头，停止执行
    [exit]
go east
@print 已发送进入墓园命令，请看服务器是否给出本轮谷主提示
```

然后由20点触发器调用它。
这个例子会真实向东移动，不要当成无动作测试运行。
房间名检查只能检查当前位置，不能证明后台任务阶段已经完成；前置必须由玩家自己确认。
已提前结算过这一轮剧情的角色，20点再进墓园并不会自动重新结算。
提前走进墓园可能提前消耗这次剧情结算，别在测试时误点。

五、收到成功提示后，自动提醒自己

新建触发器：
名称：药王谷成功提示
事件：新提示信息
关键字：你成为本轮药王谷谷主

动作源码：

```flow
@off 药王谷成功提示
@off 药王谷20点启动
@print 已收到服务器确认：你成为本轮药王谷谷主
@beep
```

活动前开启它；收到成功提示后，它会自我关闭并提醒。
这里用的是“新提示信息”，不是聊天频道中的“新聊天信息”。
别人聊天说“我抢到了谷主”，不是你成功。
源码中的个人成功提示是“你成为本轮药王谷谷主……”，应该用这类明确反馈做依据。

重要：@print 是插件自己打印的文字，不代表服务器判定。
不要在主流程最后直接写“抢首通成功”，否则哪怕任务失败也会显示成功，容易误导自己。

六、最常用的条件判断

下面是独立的演练流程，可另存为“条件判断测试”：

```flow
[if] (:combating) == true
    @print 当前正在战斗，停止本次流程
    [exit]
[if] (:free) == false
    @print 角色不空闲，停止本次流程
    [exit]
[if] (:hpPer) < 0.8
    @print 气血低于80%，请先恢复状态
    [exit]
[if] (:mpPer) < 0.5
    @print 内力低于50%，请先恢复状态
    [exit]
@print 脱战、动作限制、气血和内力检查通过
```

(:hp) 与 (:mp) 是当前气血、内力的实际点数，不是百分比。
(:maxHp)、(:maxMp) 是对应上限值。
(:hpPer)、(:mpPer) 是0到1的比例：0.8代表80%，0.5代表50%。
别把 (:hp) < 80 当成低于80%，那实际是在判断低于80点气血。

只在某类房间执行：

```flow
[if] (:room 药王谷) == true
    @print 当前位置名称包含药王谷
[else]
    @print 当前不在药王谷
```

这里 (:room 药王谷) 是房间名称包含判断，不是任务资格判断。
不要单靠“人在墓园”推断他已经完成残魂环节。

缩进必须保留：
[if] 后面的条件行不缩进，属于这个条件的动作缩进四个空格。
[else] 与 [if] 对齐。

七、等待时间、等待提示、等待状态，有什么区别？

@wait 1000：固定等1秒，不管服务器有没有响应。
@until 条件：持续等待条件成立，没有自带的总超时。
@tip 文字或正则：等待符合内容的服务器提示，不是读取任务是否永久完成。

例如：
@until (:free) == true
表示等到空闲，不代表等到药王谷通关。

@tip 你成为本轮药王谷谷主
如果没有成功，可能一直等在那里。因此教程里更推荐用独立成功提示触发器通知，不让主流程无限等待。

剧情对白要根据实际文字等待；不要把所有NPC对白都写成“等1秒就下一步”。
也不要把提示出现的任何文字都当成功，先手动确认真正的成功反馈。

八、有上限地等状态，避免无限卡死

另建演练流程“最多等30秒”：

```flow
($count) = 0
[while] (:free) == false && (count) < 30
    @wait 1000
    ($count) = (count) + 1
[if] (:free) == false
    @print 等待超时，停止执行，请手动处理状态
    [exit]
@print 当前已经空闲，可以继续下一步
```

含义：最多等待30轮，每轮额外等待1秒，然后重新检查。
受执行开销、页面调度影响，实际总时长可能略长，不是精密倒计时。
这适合一般任务，不建议用它补救已经错过20点的抢跑；先处理好状态再到点启动。

九、如何限制消息触发重复执行

最简单的方法：动作第一行就关闭自己。
例如触发器名叫“药王谷成功提示”，第一行写：
@off 药王谷成功提示

不要只写 @off，必须写准确名称。
同一个提示可能因为重复查看、多条消息或重新连接再次出现；不限制就可能反复执行。

@off 触发器名：关闭未来触发，不会停止已经运行的流程。
@stop 流程名：停止已运行的指定流程，不会自动关闭它对应的触发器。
要完全停下，一般先关触发器，再在“运行中流程”里停止相关流程。

当前旧版流程的 @call 是预展开，调用出去的内容可能仍显示在触发器同名流程下面。
所以不要只盯“药王谷执行”这个名字；在运行列表里同时检查“药王谷20点启动”。
本教程不依赖嵌套 @call：药王谷执行里面不要再 @call 另一个流程，直接放自己的操作内容。
被调用流程中的 #input/#config 在旧版预展开时可能被略过，定时前就要配置好，不要到20点才等弹窗。

十、为什么到了20点没启动？

按这个顺序查：
1. 触发器是否“已开启”？上次测试后是否自我关闭了？
2. 事件是否选“时辰已到”？时、分、秒是否分别填写？
3. 设备时区与服务器时间是否对齐？
4. 游戏是否在线、在前台？手机有没有锁屏？
5. 流程名称是不是完全一致？有没有多余空格？
6. “药王谷执行”是否已经保存，能否手动运行测试版？
7. 是否被空闲／房间条件主动拦下？查看插件输出。
8. 当前是否有别的挂机流程持续切状态或移动？
9. 是完全没触发，还是触发了但服务器拒绝移动／剧情未完成？这两类问题不要混为一谈。
10. 页面是不是刚好卡顿错过了那一秒？精确秒触发没有保证补跑。

十一、活动前检查清单

□ 完成一次无动作定时演练。
□ 确认服务器20点对应本机几点。
□ 角色前置任务已经满足。
□ 站在流程要求的起点。
□ 气血内力足够，武器内功装备正确。
□ 关闭其他自动移动、自动打坐、自动任务流程。
□ 普通流程名称与 @call 后的名字一致。
□ 定时触发器已开启。
□ 成功提示触发器已开启。
□ 保持游戏在线前台，不锁屏、不刷新页面。

最后再强调：
“到点触发”是客户端行为；“首通／谷主归属”是服务器结算。
这份教程教你正确接上触发条件和操作流程，不承诺抢到名额，也不绕过任务前置。
