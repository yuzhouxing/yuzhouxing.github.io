插件流程零基础教程
——从不会写，到能自己保存一个简单流程

适用：游戏内“工作流程”编辑器，按当前 WSMUD2 插件界面整理。
这是普通玩家教程，不需要GM权限，不用F12，也不用写JavaScript。

一、先明白：流程是什么？

流程就是把你平时手动做的几件事，按顺序写下来，让插件替你执行。
例如：查看房间 → 等1秒 → 再查看房间 → 显示完成。
不是写“去某个地方”“跟某人说话”这样的中文愿望，而是填写游戏实际使用的命令。

先分清三个东西：
1. 游戏指令栏：平时输入单条游戏命令的地方。
2. 工作流程：保存一整段操作，本教程使用这里。
3. 触发器：遇到某个事件才自动执行，新手先不要同时学习。

不要把下面的整段流程贴到聊天频道或F12里。

二、第一次怎么新建？

1. 打开插件入口，找到“工作流程”。
2. 如果打开后显示“运行中流程”，先点返回，回到工作流程列表。
3. 点右上角“选择操作” → “新建流程”。
   使用旧界面的玩家，找到“流程”里的“新建”即可。
4. 名称填写：新手测试。
5. 大文本框填写下面五行，不要复制前后的说明文字：

@print 开始测试
look
@wait 1000
look
@print 测试完成

6. 点“保存”。
7. 回到列表，点“▶️新手测试”运行；左边的齿轮是编辑，不是运行。

这个例子只查看房间，不移动、不战斗、不花钱、不丢东西。
尽量站在安全房间、没有战斗或打坐等状态时测试。

三、这五行是什么意思？

@print 开始测试
只在自己的插件消息里显示“开始测试”，不是发到公共频道。

look
查看当前房间。

@wait 1000
额外等待1000毫秒，也就是1秒，再继续下一行。

look
再次查看房间。

@print 测试完成
显示“测试完成”。后面没有命令，流程自然结束。

时间换算：
500毫秒 = 0.5秒
1000毫秒 = 1秒
3000毫秒 = 3秒
10000毫秒 = 10秒

注意：普通命令本身还可能有行间延迟，所以流程总耗时不一定只有@wait填写的时间。

四、不知道按钮对应什么命令，怎么办？

不靠猜，也不用背。先手动做一次，再看插件显示的命令。

1. 把游戏里的“代码：关”点成“代码：开”。
2. 手动点一次你要做的操作，例如查看房间、走向一个相邻房间。
3. 从回显中找到这一操作实际发送的命令。
4. 只复制命令本身，不复制时间、颜色标签、“执行系统命令”等提示标题，也不要把整段服务器数据一起粘进去。
5. 粘到流程里，一条命令一行。
6. 重复以上步骤，把两三步手动操作先拼起来测试。

例如，点击北面的相邻房间，实际命令通常是：

go north

在流程中填写go north，不是填写房间按钮上的中文名字。
特殊入口、跳跃、机关、传送不一定用go，必须以你实际操作时显示的命令为准。

提醒：“代码：开”只是显示信息，并不会自动替你录制和保存完整流程。

五、最常用的基础写法

look                 查看当前房间
go north             往北走
go south             往南走
go east              往东走
go west              往西走
go northeast         往东北走
go northwest         往西北走
go southeast         往东南走
go southwest         往西南走
go up                往上走
go down              往下走
go out               走“外面/退出”这个出口
@wait 1000           额外等待1秒
@print 任意文字      给自己显示一条提示
@cmdDelay 1000       把本流程普通命令的行间间隔设为1000毫秒

方向命令必须有对应出口才有效。
尤其不要在陌生副本里随便测试go out，它可能直接离开当前区域。

最开始一行只写一条命令，不要把所有命令挤到一行。
不要以为设置了@cmdDelay，分号连接的一串命令也会逐条等同样的时间。

六、第一次写自己的走路流程

先找一段你确认安全、确实能够往返的普通地图。
下面只是“北走一步、南走一步”的练习，必须先确认两个出口都存在；不要在机关、单向出口或副本里直接照跑。

@cmdDelay 1000
@print 开始走路
go north
@wait 1000
go south
look
@print 走路结束

制作自己的路线时：
先手动站到固定起点 → 打开代码显示 → 手动走通 → 按顺序记录命令 → 回到同一起点 → 运行流程。

同一段路线换了起点就可能走错。
每次只新增两三条命令，确认正确后再往后加。

七、怎么暂停、停止和修改？

暂停：进入“运行中流程”，点对应流程旁的⏸。
继续：点▶️。
停止：点该流程的“⏹流程名”。旧界面可能直接显示“停止”按钮。

关闭插件面板，不等于停止流程。
停止一个流程，也不等于停止其他触发器、自动任务或已经开始的游戏行为。
如果人物还在打坐、疗伤，要再使用游戏本身的停止动作；如果还在战斗，要按正常战斗规则处理。

修改：先停止正在运行的旧流程，再点列表左边的齿轮。
改完后点“保存&返回”（旧界面点“保存”），再重新运行。
保存了新内容，不代表已经运行中的旧流程会自动改用新内容。

八、想重复三次，怎么写？（前面学会后再看）

下面只查看房间三次，不进行其他操作：

($count) = 0
[while] (count) < 3
    look
    @wait 1000
    ($count) = (count) + 1
@print 三次查看完成

($count) = 0：从0开始计数。
[while] (count) < 3：不到3次，就继续执行下面缩进的三行。
($count) = (count) + 1：每做完一次，计数加1。

循环里的三行前面都有四个英文空格，不能随便删掉。
“@print 三次查看完成”前面没有空格，表示循环结束后再执行。
新手先用有限次数，不要直接写无限循环。

九、遇到问题，按这个顺序检查

1. 一点反应都没有：检查插件是否启用，流程是否保存，点的是运行还是编辑。
2. 提示不认识@wait：可能把流程内容发到了普通游戏指令栏；请在工作流程中保存、运行。
3. 一开始就走错：检查起点，确认与手动记录时的起点一致。
4. 中途不动：检查人物是否忙碌、战斗、打坐、昏迷，或正在等一个尚未满足的条件。
5. 经常漏步骤：先用一行一条命令，增加必要等待，避免多个自动流程同时操作角色。
6. 一直反复走动：检查是否重复启动，或者其他触发器、自动任务也在发送移动命令。
7. 提示找不到NPC或物品：确认目标还在当前房间或背包；临时ID可能随刷新改变，不能把某次的编号当永久编号。
8. 循环报错：检查括号、英文符号和缩进。不要把中文全角括号、分号混入语法。

多等1秒不等于自动等到战斗结束，也不等于NPC一定刷新。
需要等战斗、提示或目标出现的流程，先把基础顺序流程写通，再学习相应的等待条件。

十、新手先记住这五句话

先手动做通，再写流程。
不会的命令，打开代码显示看实际操作。
一行一条，先写两三步。
先学保存、运行、停止，再学循环和触发器。
不运行来源不明的@js、#js或出售、丢弃、转账脚本。

本教程只新增说明文档，不修改游戏或插件功能。
